# matt's thoughtscape: project brief

A personal media review site presented as a spatial canvas styled like a black cutting mat. Movie reviews sync from Letterboxd into a database, and each review appears as a poster card placed on the mat. The site owner (Matt) arranges card positions by hand in a private admin mode, and every visitor sees that same arrangement. This is not a portfolio piece in style: it should feel like a personal object, closer to a workbench than a website.

Live design reference: Figma file "Untitled" (key 2xk7Ohv28hGKhGmmBXUEp6). Pages: "Page 1" holds the canvas view ("zoomed out spread out"), the details view ("details"), and V2 concept frames ("STACKED MATS", "PEEL"). The "components" page holds masters ("zoomed out card," "hover details," "button"). This is the source of truth for visual details — the Figma MCP tools can read it directly (`get_metadata`, `get_design_context`, `get_screenshot` against file key `2xk7Ohv28hGKhGmmBXUEp6`); re-check it rather than trusting this prose if the two ever disagree. Verified details as of 2026-07-08:

- Mat background `#19191b`. Grid: 40px minor lines, brighter major lines every 200px (5th line). Rendered as a single tiled SVG data-URI image, not stacked CSS gradients — hard-stop gradient lines rasterize inconsistently across device pixel ratios (verified: invisible on some Windows scaling factors, overly heavy on others). A baked vector tile scales like a normal image instead.
- Type is **Roboto Mono** (not Space Mono), Regular/SemiBold. Ruler tick numbers use Inter Regular 9px, color `#737378`.
- Cards have **no cream border** — a thin `0.5px solid rgba(117,117,117,0.25)` border, rounded top corners only (2px). Poster is 140x210, `object-cover`. Figma's own component has no size boost for 5-star entries, but Matt asked for one anyway as a build-time deviation: 5-star posters render 15% larger (140x210 → 161x241.5) on the canvas to stand out. The boost is suppressed while a card is selected/mid-zoom, since the click-to-detail camera math (`src/lib/detailLayout.ts`) assumes every card is exactly 140x210 — see `--card-scale` in `Card.tsx`/`Card.module.css`.
- Star rating is 5 SVG stars (16px pitch, ~84x20 total box), filled color `#E0EA5E`, unfilled stars are a dim placeholder (`rgba(255,255,255,0.15)`) — exact "unfilled" treatment wasn't in the file and is our best-guess fill, open to Matt's revision.
- A white "NEW" pill badge (black text, rounded 4px) appears on some cards in the mock. Confirmed with Matt: it flags entries **synced within the last 7 days**, keyed off `created_at`. Not a placement indicator.
- Corner "MAT 01"-style stamps only appear in the V2 concept frames (stacked mats / peel), **not** in the v1 "zoomed out spread out" frame. Don't build one for v1.
- Hover popover ("hover details" component): 4px padding, white title + `#a5a5a5` "Directed by X", positioned to the right of the card. Figma specs a `rgba(155,155,155,0.25)` background, but Matt overrode it in build: over real poster art that translucency drowned, so the shipped value is near-opaque dark (`rgba(43,43,46,0.95)`). The hovered card also gets `z-index: 10` so the popover always floats above overlapping neighbor cards.
- The reset-view button (labeled "reset view", lowercase) is **not** anchored bottom-right — it's horizontally centered, positioned near the bottom. A designer annotation on the node says to only show it once the view is panned at least half a screen away from center; it's hidden otherwise.
- Details view: 320x480 poster left, 360px-wide text column right with a 24px gap; title/director/stars in one row, review text below; prev/next are icon-only arrow buttons bottom-right of the content block; a "back to canvas" button (same style as reset-view) sits centered near the bottom, same position formula as the canvas view's reset button.

## V1 scope (build this, nothing more)

One mat, every unshelved entry (the original 40-card cap was removed 2026-10-19). **Originally movies only; books shipped since** (Goodreads, `media_type: 'book'`) and share the same table, mat, canvas and detail view. Still no songs, still one mat — and the peel/stacked-mats idea is now cancelled outright (see V2). Desktop only; mobile can show a simple fallback message or a basic list, lowest possible effort.

### Core experience (public)

1. Full-viewport cutting mat: charcoal background, grid, site title "matt's thoughtscape" with subtitle "entryway to my opinions about different forms of media" near center. No corner label stamp in v1 (see Figma notes above — that's a V2-only element).
2. Every unshelved entry as a poster card at its stored x/y position (no cap). Cards are poster art only (no title text; the poster carries it), 2:3 aspect ratio, 140x210px, thin subtle border (not cream — see Figma notes), soft shadow on hover. Star rating sits below the card in chartreuse (#E0EA5E). 5-star entries render 15% larger (see Figma notes above) to stand out on the mat.

   **Book cards** differ deliberately (`BookCover` in `Card.tsx`): a fixed 140px width with the height following the cover's **own aspect ratio** (a plain `<img>`, not a background-image box, since book covers aren't a uniform 2:3), **no border**, no resting tilt, and no 5-star size boost. Their one distinguishing cue is a bottom-right **page curl** whose fold geometry is lifted directly from the Figma exploration (node 120:78) rather than approximated: a flat cream "page" layer sits under the clipped corner so the mat never shows through, then a blurred dark stroke traces the fold, the flap fill with its own cast shadow, and a thin light stroke on the cut edge only. Gotcha: the cover `<img>` needs `draggable={false}` or the browser's native image drag pre-empts the custom drag/pan (fixed in `a737378`; the shelf hit the same thing).
3. Pan the canvas by dragging. Releasing a drag mid-motion glides to a stop (ease-out tail of the same curve family, distance from release velocity, capped at 900px; a pause before release means no glide). Scroll-wheel zoom (built): cursor-anchored, clamped 0.4x–2.5x, each wheel tick retargets a short 250ms eased glide (same curve as the detail zoom) instead of stepping. Opening a detail from a zoomed camera and closing it restores the exact zoomed view; reset-view glides pan and zoom home together and also appears when zoom drifts >0.15 from 1:1. The admin canvas has the same wheel zoom; its card-drag deltas are divided by the zoom factor so a card still tracks the cursor exactly at any scale, and the shelf's drop point is converted back through the same transform (`(screen - pan) / zoom`).
4. Hover a card: a small details popover appears beside it (title, "Directed by [director]" if available). Committed animation, not cursor-tracking: once triggered it plays fully and stays until dismissed.
5. Click a card: details view. Large poster left; title, director, stars, and review text right; a visible "back to canvas" control plus Escape both close it. **Click-outside does NOT close it** — Matt found that annoying and explicitly asked for it to be removed; only Escape and the button do. Prev/next arrows step between reviews. Exact layout in Figma notes above. Books show "Written by X" where movies show "Directed by X", same slot.

   **Spoiler-flagged reviews** start behind a `blur(6px)` and reveal on click (`16a6e43`). Dimmed as well as blurred — at full opacity the hidden text is bright and busy enough to pull the eye toward the thing it's hiding, and it muddies the label on top. The cover is a real `<button>` spanning the whole block (focusable, Enter/Space work) labelled "contains spoilers / click to reveal" as bare text, no pill, since it isn't a navigation control. While hidden, `overflow` is clamped and selection is off so the text can't be scrolled to, found via find-in-page, or dragged out of the blur. The reveal is keyed to the **entry id**, not a boolean: `DetailsView` isn't remounted between entries, so arrowing from one spoiler review to another must re-hide rather than carry the previous reveal over.

   The transition is a camera move, not a cut: clicking a card animates the canvas's own pan/scale transform (~700ms ease-in-out) so the clicked card grows into the poster's position/size, with every other card and the grid along for the ride (same transform, so they naturally slide/scale past the viewport edges — this "other cards passing by" look falls straight out of sharing one transform, no special-casing needed). The card's resting tilt eases to 0° and its star row fades out in sync (the detail text panel shows its own rating); the NEW badge **stays visible** on the zoomed poster — Matt explicitly wants it kept in the detail view. The text panel itself fades/slides in only during the last ~40% of the move. Exiting (button or Escape) reverses the same tween back to the pan position you were at before opening. The arrow buttons fly between cards (450ms, shorter than open/close) without a detour through the canvas view. Arrow navigation is **spatial, not chronological** (Matt's explicit preference after trying both): each arrow flies to the nearest card (Euclidean distance) whose x lies strictly in that direction, and disables when nothing exists that way. Any other card still visible at the edges of the detail view is also clickable and flies the camera straight to its own detail (same machinery). `prefers-reduced-motion` skips the tween entirely (snap + CSS opacity crossfade). The URL syncs to `/film/<slugified-title>` via plain `history.pushState`/`replaceState` (not Next.js routing) specifically so the canvas component is never remounted mid-transition; a `popstate` listener handles back/forward. Real `/film/[slug]` and `/book/[slug]` routes also exist (both render the same Canvas) purely so hard loads/refreshes of a detail link don't 404 — the Canvas reads the path on mount and opens that entry. `detailPath()` in `detailLayout.ts` picks the prefix by `media_type`. Geometry/easing/animation-driver code lives in `src/lib/detailLayout.ts`, shared between the camera math and the text panel's fixed screen position so they always line up exactly. Books needed that math generalised (`f176b53`): scaling a movie card by `ZOOM_SCALE` always lands on the fixed 320x480 poster rect, but a book's detail height is whatever its own card height scales up to, so `posterHeightFor()` takes the book's real rendered world height — which `Canvas.tsx` learns from the loaded `<img>` via `onBookHeightKnown`, falling back to the movie height until then — and the text column and nav row sit against that instead of an assumed 480.

   Gotcha (hit once, don't reintroduce): the viewport must use `overflow: clip`, not `overflow: hidden`. `hidden` still permits programmatic/focus-triggered scrolling, and any such scroll silently offsets the whole world from the camera math (surfaced as a card landing exactly 40 world-px off-target after clicking a partially-offscreen card). Non-clickable cards (the selected one, or all cards mid-flight) also get a `noHover` class that suppresses the hover lift and pointer cursor.
6. Wayfinding: a reset-view control, labeled "reset view", horizontally centered near the bottom — only shown once panned at least half a screen away from center (not always visible, not bottom-right). "Center" means the title copy sits at exact viewport center (Matt's call after trying bounding-box-of-all-cards centering, which drifted with asymmetric arrangements), and reset glides there with the same 600ms ease as the detail zoom rather than snapping. **Ruler** (built: `src/components/Ruler.tsx`) along the **top and left** edges — plain small numbers per the Figma spec (Inter 9px, `#737378`), not literal tick lines.

   It's a **screen-fixed overlay, not part of the world transform** — a ruler taped along the edge of the mat rather than printed on it. But the numbers it prints are world coordinates, so panning scrolls them and zooming spreads or compresses them. That's why it can't just live inside `.world`: it has to reverse the camera, `world = (screen - pan) / scale`, to work out which world coordinates are currently on screen.

   - **Adaptive spacing.** Candidate steps are `[40, 200, 400, 1000, 2000]` world px — every one a multiple or divisor of the grid's 200px major spacing, so a label always lands on a real grid line instead of floating between them. It picks the smallest step whose *on-screen* gap clears 90px, so the ruler thins out as you zoom out and gets finer as you zoom in.
   - The first 28px of each edge is left blank, or the top and left labels collide in the corner.
   - Labels are centred on their line (`translateX/Y(-50%)`), not started at it.
   - A two-layer mat-coloured `text-shadow` halo keeps the numbers legible where cards pan underneath: invisible against the mat itself, but a mid-grey number on bright poster art washes out without it.
   - `pointer-events: none` at `z-index: 5` — above the world, below the reset button and detail view — so it never eats a drag.
   - It's fed the canvas's `camera` rather than raw pan/zoom, so it tracks the camera through the detail-zoom tween too, and fades to 0.25 opacity (300ms, matching the grid) whenever the detail view is open.
   - Currently **live canvas only** — `AdminCanvas` doesn't render it.
7. Review text is expected to be short (a few sentences). Still cap the container and scroll on overflow so a long review never breaks layout.

### Admin mode (private)

A route not linked anywhere, gated by a simple password check (an environment variable is fine; this is privacy, not security).

1. Same canvas, but cards are draggable. On drop, persist the new x/y to the database (built: `/api/position`, service-role write gated on the admin cookie; anon key stays read-only via RLS).
2. The "ADMIN MODE" status line sits centered at the top as **bare chartreuse text** — no fill, no radius, no shadow plate. With a `#2d2d2d` plate behind it it read as a button, which it isn't; it's a status line, so it follows the spoiler label's treatment instead (a text-shadow as the only concession to legibility over poster art). Its chartreuse is `#E0EA5E`, the same token as the star fill — it was previously `#d8e04a`, a second near-identical green with nothing distinguishing it. Behind the words sits a feathered `blur(4px)` haze (`.badgeBlur`) so chartreuse stays readable where a bright poster pans under it. It's a separate layer, not a background on the badge: it bleeds past the text box without padding (so the copy doesn't shift) and it can be masked, whereas masking the badge itself would fade the outer letters. The radial mask matters — an unfeathered backdrop blur is a crisp-edged rectangle, i.e. the plate again by another route.
3. A "Sync now" button (built: top-right of the admin canvas): sync is manual only, never scheduled. It fetches the Letterboxd RSS feed, parses entries, and upserts into the database, reporting "N new · N updated" in the admin badge and reloading to show new cards.
4. New entries from sync get an auto-jittered starting position (random within a sane region) so nothing ever sits unplaced; Matt then drags them where he wants.
5. A "back to live" button sits bottom-center — same position and style as the live view's reset-view/back-to-canvas buttons, admin mode only. It navigates to `/` without clearing the admin cookie (30-day session), so hopping between arranging and previewing doesn't re-prompt for the password.
6. **The shelf** (built: `src/components/Shelf.tsx`) — admin-only, and the answer to "get this card off my mat." Hovering a card reveals a neutral X at its top-left (`hideButton` in `Card.module.css`); clicking it sets `shelved_at` and the card drops into a drawer that pulls up from the bottom of the screen. **There is no hard delete anywhere in the app** — Matt's explicit call. Rows are never removed, only hidden, so every hide is reversible forever and the shelf is unbounded.
   - The pill riding the drawer's top edge is the handle: click to toggle, or drag to one of three rest heights (0 / 196 / 380, snapping to the nearest on release, with 40px of overdrag give). Peek shows cover + stars; fully open adds title and a one-line truncated review. Copy is "hidden entries · N" closed, "close shelf" open. Only the small grab bar shows the `ns-resize` cursor — Matt's call, since a resize cursor across the whole pill implied the label was a drag handle. Dragging still initiates anywhere on the pill; it's just the cursor hint that's narrow.
   - The shelf **wraps and scrolls vertically** (Matt's explicit correction of the original horizontal rail). Covers carry the *same* `0.5px rgba(117,117,117,0.25)` hairline as the card on the mat rather than a second formulation of it, and are a fixed 100x150 — a true 2:3, matching the mat card's 140x210 exactly (the Figma Make exploration's 148 was 0.676, which cropped a sliver off every poster and left the hide animation morphing aspect mid-flight); books override the height and, books keep their own aspect ratio, and each row bottom-aligns so covers rest on a common line with ragged tops, like books on a shelf. Gotcha that follows from that alignment: the review note line is rendered even when there's no review, because the row aligns whole columns — an entry missing that line would sit a line lower than its neighbours and break the baseline (verified: it produced a 15px spread across one row).
   - Pressing the X plays a committed sequence rather than cutting: the drawer opens to peek, the card flies from where it sat on the mat into its shelf slot, sits there for 260ms, then the drawer closes. The flight is 600ms total, and the lift and the travel are deliberately **separate durations**: the 7% swell arcs across the whole 600ms, while the position move is a snappier 380ms *delayed* to the last 380ms (`TRAVEL_DELAY_MS`). So the card swells 7% in place — peaking at 129ms, 91ms before it starts moving at all — holds near full swell for a beat, then gets whisked to the shelf while deflating. The two must **end together**: if the swell hasn't returned to 1 when the card reaches its slot, it lands oversized and then visibly resizes, which is why the travel is delayed rather than slowed. Verified: it lands at the slot rect with zero error on both axes. The flight is therefore driven **linearly**, with both curves applied per frame — the lift keys to elapsed time, not to eased distance, or the swell would arrive after the card had already gone. Tuning knobs: `LIFT_SCALE` for how much, the `0.45` exponent in `liftAt` for when it peaks, `TRAVEL_MS` for how fast it crosses.
   - Gotcha that cost a visible bug: `liftAt` **must clamp its input**. `animateValue` computes `raw = (now - start) / duration` with no lower bound (`detailLayout.ts`), and a rAF timestamp can predate the `performance.now()` captured just before the loop starts, so t can arrive slightly negative — and `Math.pow` with a fractional exponent returns NaN for a negative base. That NaN became an NaN width, which the browser *silently drops*, painting the cover at full intrinsic resolution for one frame. It showed up as a huge flash on book covers (Yellowface is 1593x2400) and was easy to miss on 600x900 posters. `.flight` also carries fallback `width`/`height` in CSS purely as a net for this class of failure — the inline values always win, but a dropped declaration now lands on shelf-card size instead of full resolution. The entry joins the shelf list immediately so its slot is laid out and **measurable**, and that slot renders at `opacity: 0` while a flying copy covers the distance — so nothing jumps when the two swap. The target comes from the slot's `offsetLeft`/`offsetTop` against the drawer (its `offsetParent`) plus `innerHeight - targetHeight`, rather than a viewport rect that would be read mid-slide; verified pixel-exact against the slot's real position. Deriving it from the strip's padding instead would break as soon as covers wrap or a book takes its own height.
   - Two ways back onto the mat: **drag a card out** and drop it where you want (the preferred path — the drop point converts to world coords and centers the card on the cursor), or **click it** to return it to the exact position it had when hidden. Clicking works because hiding never clears x/y. Releasing a drag back inside the drawer cancels.
   - Gotchas, all hit once: the drag ghost and the flying card must render as *siblings* of the drawer, never children — the drawer is `overflow: hidden` and scrollable, so either one inside it gets clipped the moment it leaves. The pill, drawer, and shelf cards all have to `stopPropagation` on pointerdown or the admin viewport's pan handler engages underneath. Shelf images need `draggable={false}` (same native-drag conflict the book card hit). The viewport's wheel-zoom listener early-returns on any event inside `[data-shelf]` — that's both what stops the mat zooming out from under an open drawer and, by skipping `preventDefault`, what lets the drawer scroll natively at all. And the pill/card drag handlers gate on **refs, not state**: a pointermove can arrive before React commits the state set on pointerdown, and a handler closing over the stale `false` would drop the move (this is why the original Figma Make prototype used a ref here too).
   - The drawer sits at `z-index: 30` and the pill at 40, above every admin control (all `z-index: 10`), so it simply **slides over** reset-view and back-to-live as it opens. Nothing repositions to make room — Matt's call, and it means the shelf's Figma geometry needed no adjustment. Those buttons are unreachable while the shelf is open, which is intended: an open drawer is a mode.
   - With no cap on the mat (removed 2026-10-19), shelving is the only way to take a card off it — nothing rotates in to replace it.

### Data pipeline (movies verified 2026-07-08; books added since)

- Source: Letterboxd RSS at `https://letterboxd.com/matttheinn/rss/`. Parser lives in `src/lib/letterboxd.ts`; the admin-gated route `src/app/api/sync/route.ts` does the upsert. Verified against the real feed: 50 items imported, second run = 0 new / 50 updated (idempotent).
- Fetch server-side (CORS blocks browser fetches of this feed). Feed facts, verified: guids look like `letterboxd-review-<id>`; film reviews carry `letterboxd:filmTitle/filmYear/memberRating/watchedDate`; the description CDATA holds a 600x900 poster `<img>` (plenty for the 320px detail poster) followed by review paragraphs. Watch-only entries have an auto-generated "Watched on <date>." paragraph — the parser strips it rather than storing it as a review. Items without `filmTitle` (list activity) are skipped. **Director is not in the RSS at all** — sync backfills it by fetching each film's Letterboxd page and reading the schema.org JSON-LD it embeds (`fetchDirector` in `src/lib/letterboxd.ts`, concurrency 5, only for rows where director is still null, so after the first full pass only new films cost a fetch). Gotcha: rewatch review URLs carry a numbered suffix (`/film/her/1/`) that must be stripped to reach the film page. TMDB (`tmdb:movieId` is in the feed) remains the upgrade path if scraping ever breaks.
- Upsert keyed on (source, source_id) so re-running sync never duplicates. Confirmed with Matt: sync updates existing rows (edited reviews propagate), not insert-only. Updates never touch x/y (hand placement survives) or `shelved_at` (a hidden entry stays hidden across re-syncs) — both fall out of the update branch spreading only the parsed feed fields, the same protection the rating fix relies on. Only brand-new rows get a jittered position (x 200–1200, y 150–700).
- `logged_at` = `letterboxd:watchedDate` (fallback pubDate), so the canvas's ordering follows watch order, not posting order.
- Canvas queries every unshelved entry by logged_at. The 40-card "rotate off" cap was removed 2026-10-19 at Matt's request; the mat now grows with every sync, and new entries still land in the jitter region for hand placement.
- The dummy seed rows were deleted once the real sync was verified. `supabase/seed.sql` remains only as a reference for spinning up a fresh dev database.

**Books (Goodreads).** Second source, same pipeline. Parser in `src/lib/goodreads.ts`; the same `/api/sync` route fetches both feeds in parallel and upserts each through one shared `syncSource(source, mediaType, parsed)`, so movies and books never diverge in upsert behaviour. Feed: `https://www.goodreads.com/review/list_rss/199102300?shelf=read`. Verified feed facts:

- The `guid` is **per-review, not per-book**, so a reread creates a new entry rather than colliding — deliberately the same behaviour as a Letterboxd rewatch.
- `user_rating` of **0 means "marked read, not rated"**, not zero stars, so it's stored as null. This is what the `dde93bd` fix is about: Goodreads keeps reporting a freshly-added rating as 0 for a while, so the sync's update branch omits the `rating` key entirely when it parses null rather than writing null over a good stored value.
- `user_read_at` is blank for most entries in practice; `user_date_added`/`pubDate` are always populated and identical, so `logged_at` falls back to `pubDate` (same shape as Letterboxd's `watchedDate` -> `pubDate` fallback).
- `author_name` comes straight from the feed, so books need **no equivalent of the director backfill** — that scrape is Letterboxd-only.
- `book_large_image_url` is the cover. These are much larger than Letterboxd's 600x900 (Yellowface is 1593x2400), which matters: anything rendering a cover needs an explicit size, or a dropped CSS declaration paints it at full resolution (this is exactly how the shelf's NaN-width bug surfaced).
- `user_review` arrives with paragraph breaks already stripped by Goodreads, so `cleanReview` only decodes/strips stray markup and trims — there's no structure left to reconstruct.
- `htmlEntities: true` on the XML parser, same as Letterboxd: both feeds encode apostrophes as numeric entities in plain fields.

**Spoilers (Letterboxd only).** `contains_spoilers`, detected in `src/lib/letterboxd.ts` from **two independent signals** — a `(contains spoilers)` suffix on the item `<title>` and a "may contain spoilers" line in the description — because either alone is enough and checking both survives Letterboxd dropping one. Letterboxd's own "This review may contain spoilers." boilerplate paragraph is stripped from the stored review (it's chrome, not Matt's writing); the site renders its own treatment off the flag instead. Goodreads has no equivalent, so its adapter leaves the key undefined and the column keeps its `false` default — the upsert only sends `director`/`author`/`contains_spoilers` when the adapter actually set them.

### Database (Supabase, Postgres)

```sql
create table media_entries (
  id uuid primary key default gen_random_uuid(),
  source text not null,              -- 'letterboxd' | 'goodreads'
  source_id text not null,           -- stable id or URL from the source
  media_type text not null,          -- 'movie' | 'book'
  title text not null,
  year int,
  director text,                     -- movies only
  author text,                       -- books only
  cover_url text,
  rating numeric,                    -- normalized 0-5
  review_text text,
  contains_spoilers boolean not null default false,  -- letterboxd spoiler flag; books always false
  logged_at timestamp not null,
  shelved_at timestamptz,            -- non-null = hidden from the mat, in the admin shelf
  external_url text,
  x numeric,
  y numeric,
  mat_number int default 1,          -- vestigial; the v2 chapters idea was cancelled
  created_at timestamp default now(),
  unique (source, source_id)
);
```

The polymorphic shape paid off: books needed no schema change beyond adding `author`, just new `source` and `media_type` values. Songs would be the same. `supabase/schema.sql` is kept complete (not just the original cut), with `add_spoilers_column.sql` and `add_shelved_column.sql` alongside it for applying those two columns to an existing database.

### Stack

Next.js + Supabase + Vercel. Matt is learning React fundamentals alongside this, so favor clear, well-commented code over clever abstractions. Hand-roll the pan/zoom canvas with CSS transforms (or d3-zoom); do not pull in a whiteboard library like tldraw. Owning the rendering matters because the distinct visual style is the point. Avoid leaning on default Tailwind styling for the expressive parts; the mat, cards, and type treatment should be deliberate custom CSS.

#### CSS authoring rules (read before writing any CSS here)

**Never hand-write a vendor prefix.** The build pipeline adds whatever the targets need. Writing one yourself is unnecessary, and in one specific order it is destructive: a rule with the unprefixed property **followed by** its `-webkit-` twin has **both declarations silently dropped in `next dev`** — the rule is served completely empty.

Isolated by probe, using `backdrop-filter`:

| What the source says | What `next dev` serves |
| --- | --- |
| `backdrop-filter` alone | kept |
| `-webkit-backdrop-filter`, then `backdrop-filter` | kept (prefix discarded as redundant) |
| `backdrop-filter`, then `-webkit-backdrop-filter` | **nothing — whole rule emptied** |

The production build keeps the property in all three cases, so the symptom is an effect that works deployed and is invisible locally — which reads as "the change didn't apply" and sends you looking in entirely the wrong place. This cost a wrong diagnosis once already: two sightings of the bad pattern looked like "the dev server strips `backdrop-filter`", which is false and would have meant avoiding a perfectly good property forever.

Checked at the same time and all passing through dev untouched: `mask-image`, `clip-path`, `aspect-ratio`, `mix-blend-mode`, `container-type`, `text-wrap: balance`, `overscroll-behavior`, `oklch()`, `position: sticky`. Modern CSS in general is fine — the hazard is only the prefix ordering.

The `-webkit-` declarations that remain in the repo are safe and intentional, because none has an unprefixed counterpart in the same rule: `-webkit-font-smoothing` (`globals.css`), `-webkit-user-drag` (`Card.module.css`), `::-webkit-scrollbar` (`Shelf.module.css`).

**Corollary:** if a style looks right in production but missing in `next dev`, suspect the served CSS before suspecting the component. `[...document.styleSheets]` → find the rule → read its `cssText` shows you exactly what the pipeline emitted.

### Interaction feel (from an already-built prototype)

A working React prototype of the mat exists (mat-peel-prototype.jsx) and its card/mat styling tokens can be lifted directly. Key learnings from it:
- Animations should commit: trigger once, play fully, rest in the new state. Never tie animation progress to cursor position.
- Card hover: slight lift (translateY -4px, scale 1.03) with a deeper shadow, ~180ms ease.
- The prototype's cream card borders and mat shadow are its own V2-peel styling — the actual v1 card component in Figma uses a much thinner, near-invisible border instead (see Figma notes at the top of this file). Follow Figma for the card; follow the prototype for animation feel and the peel mechanics.
